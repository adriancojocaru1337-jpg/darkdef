# v0.11.33 — Story leaderboard reliability

## Problem

Story Rankings was submitted after every campaign stage. A fast campaign using
x2/x3 could reach the per-name submission limit before Stage 12, causing the
final Act II result to be rejected while earlier, weaker stage rows remained.

The Rankings page also rendered only the public Top 10. A valid signed-in score
outside that list looked identical to a failed submission.

## Fix

- Story now uses one campaign run token across stage transitions.
- Act I creates a durable campaign checkpoint on the same `run_id`.
- Act II updates that row and finalizes the token.
- Intermediate stages no longer generate twelve independent submissions.
- Expired tokens are refreshed before the first wave, including tokens restored
  from an older save.
- The x3-aware runtime plausibility check remains active.
- `get-leaderboards` returns the authenticated player's global Story and Endless
  rank in addition to the public Top 10.
- Rankings renders a separate `YOUR RANK` row when the player is outside Top 10.

No database schema migration is required. Deploy the static site and Netlify
Functions together so the new campaign checkpoint semantics are active on both
client and server.
